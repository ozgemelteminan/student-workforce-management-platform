# API Architecture

The API project owns HTTP concerns only. Domain rules remain in `StudentWorkforceManagement.Domain`, use cases remain in `StudentWorkforceManagement.Application`, and persistence/provider details remain in `StudentWorkforceManagement.Infrastructure`.

## Versioning

The first API surface is rooted at `/api/v1`. Version constants live in `StudentWorkforceManagement.Api.Contracts.V1.ApiRoutes`, and v1 endpoints are mapped from `StudentWorkforceManagement.Api.Endpoints.V1Endpoints`.

## HTTP Composition

`Program.cs` registers Application, Infrastructure, then API services. Runtime middleware order is:

1. Problem/exception mapping
2. HTTPS redirection and security headers
3. CORS
4. JWT authentication
5. Authorization
6. Controllers, health checks, infrastructure endpoints, and v1 minimal endpoints

Minimal endpoints are intentionally thin. They bind route/query/body values, enforce endpoint-level policies where useful, and dispatch MediatR commands/queries.

## Authentication

Authentication uses JWT bearer tokens. Access tokens include user, session, role, and optional student claims. Token validation also checks the backing session row is active, not revoked, not expired, and belongs to an active user.

The SignalR notification hub accepts bearer tokens from the `access_token` query parameter only for `/hubs/notifications`.

## Authorization

Primary policies are:

- `ADMIN`
- `TASK_MANAGER`
- `REVIEWER`
- `STUDENT`
- `STAFF_TASK_MANAGEMENT`
- `REVIEWERS`

Endpoint policies provide HTTP-level coarse checks. Fine-grained IDOR checks remain in Application authorization and handlers through `ICurrentUserService`.

## Error Handling

Unhandled exceptions are normalized to ProblemDetails. Validation returns `422`, not-found returns `404`, forbidden returns `403`, conflict and concurrency errors return `409`, and unexpected exceptions return `500` without stack traces.

## Rate Limiting

Authentication-sensitive routes use a process-local `AuthAttemptLimiter` for login and forgot-password throttling. It is a safe API-layer guard, but a distributed limiter should be introduced before multi-instance production deployment.

## Files

Upload routes return signed upload contracts from Application/Infrastructure storage providers. Download routes return authorized download contracts instead of exposing filesystem paths.

## Operations

Health checks are exposed at `/health`, `/health/live`, and `/health/ready`. Hangfire Dashboard is exposed at `/admin/hangfire` and is restricted to authenticated `ADMIN` users.

## Exports

Exports use a durable asynchronous lifecycle. `POST /api/v1/exports` persists a queued request and returns `202 Accepted`; `GET /api/v1/exports`, `GET /api/v1/exports/{id}`, and `GET /api/v1/exports/{id}/download` are implemented with authorization and IDOR filtering. Export artifacts are generated by background jobs and exposed through authorized expiring download contracts.
